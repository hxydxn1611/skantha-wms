WARLOG / Skantha WMS — Multi-Site Data Isolation, Dynamic RBAC & OTP IAM Plan

Engineering & Agent Handoff Specification • Zero-Regression Architecture for 120 FPS Camera Streaming & Sub-15ms ANPR

Goal: Implement Multi-Company + Multi-State/Warehouse Data Isolation (Option 2), Dynamic Per-Warehouse RBAC (3 roles in compact sites up to 15–30+ custom roles in enterprise hubs), Role-Scoped Dashboard & AI Copilot, Salted Password Hashing, and OTP Staff Onboarding with Forced First-Login Password Reset.

1. Approved Product & Security Rules

  1. Dashboard & WARLOG AI Copilot Access: Enabled by default for all roles (dashboard:view, copilot:use), strictly filtered by active warehouse & permissions. Frontline roles only see data & Copilot answers for their authorized warehouse and allowed domains; Company Admin (*) sees complete cross-warehouse analytics and unrestricted Copilot actions across the company.
  2. Company Registration vs. Team Invites (login.html):
    • New Company Self-Signup: Allowed via OTP email verification; provisions Company + initial Warehouse + default 3-role pack and makes registrant Company Admin.
    • Existing Company Guard: Self-registration under an already-existing company name is blocked (409 company_exists_invite_required). Existing companies add staff strictly via Company Admin OTP Invites.

3. Hard Invariants (DO NOT BREAK)

  • 120 FPS Streaming & HTTP/1.1 Connection Pool: Preserve lazy data-stream-src, window.syncVisibleStreams(), and the 4-slot live MJPEG cap in cameras-view. Keep VisionRuntimeManager & active_cameras running by camera_id; filter API visibility rather than killing capture threads.
  • Sub-15ms Gate ANPR: Do NOT run SQLite or RBAC lookups inside _capture_loop(), _worker_loop(), _run_live_gate_anpr_worker(), or generate_frames() loops.
  • Zero-Downtime DB Migration: Use idempotent ALTER TABLE ... ADD COLUMN ... DEFAULT ... and backfill existing records to WH-MAIN / Skantha Industrial Solutions.
  • Admin Recovery Guarantee: Every company must retain at least one active Admin role with wildcard ["*"] permissions.

5. Phased Implementation Plan

Phase 1 — Schema Extensions, Password Hashing & Session Scoping (db.py, app.py)

  • Upgrade create_user() and get_user() to use werkzeug.security hashes, with silent 1-time upgrade for legacy plaintext users (e.g., admin/admin). Add must_reset_password, is_active, invited_by, last_login_at to users.
  • Add state TEXT DEFAULT 'Karnataka' to warehouses.
  • Create tables rbac_roles, user_warehouse_access, and audit_logs. Seed 3_role, 5_role, and 15_role presets + get_role_coverage() meter helper.
  • Move active warehouse state into Flask session['user'] so concurrent sessions never collide.
CREATE TABLE IF NOT EXISTS rbac_roles (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    company_name TEXT NOT NULL, warehouse_code TEXT NOT NULL, role_name TEXT NOT NULL,
    description TEXT DEFAULT '', permissions_json TEXT NOT NULL,
    is_system_admin INTEGER DEFAULT 0, is_enabled INTEGER DEFAULT 1,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP, updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(company_name, warehouse_code, role_name)
);
CREATE TABLE IF NOT EXISTS user_warehouse_access (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username TEXT NOT NULL, company_name TEXT NOT NULL, warehouse_code TEXT NOT NULL,
    role_id INTEGER NOT NULL, is_default INTEGER DEFAULT 0, status TEXT DEFAULT 'Active',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP, UNIQUE(username, warehouse_code)
);

Phase 2 — rbac_service.py, Forced Password Reset Gate & Company Signup Guard

  • Create webapp/rbac_service.py with PERMISSION_CATALOG, get_request_scope(), @require_permission(), and log_audit_event().
  • Enforce must_reset_password == 1 inside enforce_authentication_and_session(): return 403 password_reset_required on all WMS APIs until /api/auth/force_reset_password completes.
  • In /api/auth/send_otp, /api/auth/verify_otp_and_register, and /api/register: reject public registration when company_name already exists (409 company_exists_invite_required).

Phase 3 — Full Multi-Site Data Isolation & Role-Scoped Copilot (Option 2)

  • Add company_name + warehouse_code DEFAULT 'WH-MAIN' to all per-warehouse tables (cameras, vision_zones, bins, inventory, expected_deliveries, gate_passes, vehicle_log, outbound_orders, pallets, violations_log, vision_counting_submissions) and company_name to shared catalog tables (skus, sku_images, object_classes).
  • Add IDOR ownership checks on single-item routes; scope get_staging_service(warehouse_code) per facility.
  • Scope /api/stats and webapp/copilot_service.py to (company_name, warehouse_code, permissions, is_admin).

Phase 4 — IAM Onboarding UI, State → Warehouse Picker & Role Builder

  • Add /api/auth/me, /api/auth/force_reset_password, /api/iam/permissions, /api/iam/warehouses/<wh>/roles, /api/iam/users, /api/iam/audit_logs, and harden /api/warehouses/switch.
  • Admin Invite sends single-use hashed OTP via existing send_verification_email() SMTP mailer and flags must_reset_password = 1.
  • Update login.html with Forced Password Reset modal + State → Warehouse picker; update index.html & app_logic.js with IAM Panel, Live Coverage Meter, and window.hasPerm() UI gating.

6. Acceptance Verification

  1. Legacy Login: admin/admin succeeds, auto-upgrades to salted hash, and retains all WH-MAIN cameras/bins.
  2. Same-Company Guard & OTP Reset: Public signup on existing company returns 409; OTP-invited user hits 403 until password reset, and OTP cannot be reused.
  3. Scoped Dashboard & Copilot: Operators query allowed site data cleanly and receive RBAC denials on restricted modules/other warehouses; Admin has full visibility.
  4. Multi-Site Isolation & 120 FPS Cameras: Concurrent WH-A (3 roles) vs WH-B (15 roles) sessions show 100% coverage & zero data leakage while MJPEG feeds stay smooth.
