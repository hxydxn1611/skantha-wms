🏷️ Architectural Principle: Track ID ≠ Real-World Identity Identity Foundation

The system strictly separates Track ID (e.g. Track #1: temporary visual continuity in the camera session) from Real-World Identity (e.g. B104: detected from physical barcode, QR, or OCR evidence). Track IDs may disappear or restart; real-world identities persist as physical warehouse assets. Never invent or guess an identity.

Association Evidence Breakdown

🔒 Architectural Boundary: Co-Visibility Is Not Association Zero DB Writes

Part 9 establishes controlled, evidence-based relationships between Truck tracks and Box tracks. An association is never inferred simply because both objects are co-visible in the same frame. Confirmation requires sustained spatial proximity (normalized Euclidean distance ≤ 0.40), matching warehouse zone/ROI, and temporal persistence across consecutive frames (min 3 frames). Real-world identity binding (e.g. GP-1000 ↔ VLV-900) is only claimed if both underlying entities were successfully validated in Part 8. All association states are kept in-memory; zero database writes or WMS transactions are committed.
